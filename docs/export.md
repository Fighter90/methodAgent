# Выгрузка комплекта

Выгрузку выполняет `src/app/export/service.py` (навык `export`, без модели). Доступно семь форматов: программа по шаблону АЦР в DOCX, лекционные материалы в DOCX, проект приказа в DOCX, слайды в PPTX, тесты в GIFT и Moodle XML, полный комплект в JSON по схеме подраздела 4.8 ТЗ. PDF в коде не реализован. Реквизиты приказа, ФИО преподавателей и подписи остаются пустыми полями `________________`, которые заполняет человек; правило V-11 проверяет, что они не заполнены агентом. Файлы отдаёт эндпоинт `GET /api/v1/programs/{program_id}/export/{fmt}` (`src/app/programs/router.py`); ответ автопрогона содержит ссылки на все форматы в поле `files`.

## Форматы

`FORMATS = ('docx', 'pptx', 'gift', 'moodle_xml', 'json', 'order_draft', 'lectures_docx')`; функция `render(doc, fmt)` возвращает `(байты, MIME-тип, имя файла)`. Имя файла — название программы, где всё, кроме букв, цифр и дефиса, заменено на `_` (до 60 символов), иначе id программы. Неизвестный формат — `BadRequest` со списком доступных.

| `fmt` | Файл | MIME | Функция | Что внутри |
|---|---|---|---|---|
| `docx` | `<имя>.docx` | wordprocessingml | `render_docx` | Программа по шаблону АЦР с титульным листом, таблицами и приложениями |
| `lectures_docx` | `<имя>_lectures.docx` | wordprocessingml | `render_lectures` | Лекции: длительность, план по минутам, примеры кода (Courier New 10 pt), тезисы слайдов |
| `order_draft` | `<имя>_order_draft.docx` | wordprocessingml | `render_order` | Проект приказа об утверждении программы |
| `pptx` | `<имя>.pptx` | presentationml | `render_pptx` | Слайды лекций |
| `gift` | `<имя>.gift.txt` | `text/plain; charset=utf-8` | `render_gift` | Тесты в формате GIFT |
| `moodle_xml` | `<имя>_moodle.xml` | `application/xml` | `render_moodle_xml` | Тесты в Moodle XML |
| `json` | `<имя>.json` | `application/json` | `kit_json` | Комплект по схеме 4.8 |

## DOCX по шаблону АЦР (`render_docx`)

Шрифт Times New Roman 12 pt; заголовки первого уровня — зелёным акцентом (`#21A038`). Тексты разделов берутся из `doc.kit.sections`, а если их нет — собираются `build_sections` (см. [agent-workflow.md](agent-workflow.md)). Порядок и заголовки — `SECTIONS_DPP` или `SECTIONS_DOOP` из `src/app/validation/rules.py`.

**Титульный лист** (`_title_page`): строки шапки организации, реквизиты и адрес из профиля организации (`org_profile()`), блок «УТВЕРЖДЕНО Приказом № ____-<префикс> от «___» __________ 20__ г.» справа, вид программы по типу («ДОПОЛНИТЕЛЬНАЯ ПРОФЕССИОНАЛЬНАЯ ПРОГРАММА ПОВЫШЕНИЯ КВАЛИФИКАЦИИ», «… В ФОРМЕ СТАЖИРОВКИ», «ДОПОЛНИТЕЛЬНАЯ ОБЩЕОБРАЗОВАТЕЛЬНАЯ ОБЩЕРАЗВИВАЮЩАЯ ПРОГРАММА»), название, город и год создания.

**Разделы.** Текст выводится абзацами; строки «— …» — маркированным списком. Специальные разделы:

| Раздел | Содержимое |
|---|---|
| `results` (ДПП) | Первая строка текста и таблица «Виды деятельности / Профессиональные компетенции / Практический опыт / Умения / Знания» (вид деятельности — названия ТФ или направление) |
| `curriculum` | Учебный план по модулям. ДПП: №, раздел, всего, ЛК, ПР, ЛБ, СРС, форма аттестации, строки «Итоговая аттестация» и «Итого (час.)»; для стажировки в строке ИА ЛК/ПР/ЛБ равны 0. ДООП: шапка образца — общая трудоёмкость, аудиторные, теория, практика (ПР + ЛБ), самостоятельная работа, форма контроля |
| `utp` | ДПП: учебный план с темами. ДООП: таблица «Тема / Виды учебных занятий / Содержание / Часы» с содержанием тем из рабочих программ модулей и строкой ИА |
| `calendar` | Текст и таблица по неделям: учебные дни, всего, ЛК, ПР, ЛБ, СРС, ИА, содержание (до 6 тем) |
| `content` (ДПП) | Рабочая программа: раздел с аннотацией, темы с содержанием и часами по видам, текущий контроль, ИА, итого |
| `assessment` (ДООП) | Текст и таблица этапов контроля «Этап / Артефакт / Кто и как оценивает» |
| `app1` | Приложение 1: для стажировки — примерные вопросы собеседования; затем оценочные материалы текущего контроля (тесты с вариантами «а)…е)» и ключом, задания с ожидаемым результатом и критериями) |
| `app2` (только ДПП) | Приложение 2: методические указания к ИА, требования к работе, детализированные критерии с баллами, порог «зачтено» — 70 % максимального балла, процедура (выступление 5–7 минут и ответы на вопросы 5–7 минут) |

Перед каждым приложением вставляется разрыв страницы. В шаблоне ДООП одно приложение (`app1`).

|---|---|---|---|---|---|
| Разделы шаблона (`sections`) | да | — | — | — | да |
| Учебный план, УТП, календарь | да (таблицы) | — | — | — | да (модули, темы, часы, `calendar`) |
| Компетенции, индикаторы, РО, ПС | да | — | — | — | да |
| Рабочие программы модулей | да (2.4 / УТП ДООП) | — | — | — | да |
| Вопросы тестов с ключами | да (приложения) | — | — | да | да |
| Задания с критериями | да (приложения) | — | — | — | да |

## PPTX (`render_pptx`)

Формат 16:9 (13.333 × 7.5 дюйма), стиль презентации защиты: тёмный фон, зелёные акценты, шрифт Manrope. Титульный слайд — название программы, организация и список модулей. Далее по слайду на каждый слайд лекций: надзаголовок «Модуль · Тема», заголовок, тезисы в карточке с зелёными маркерами (тезис жирным, пояснение обычным), заметки докладчика, подвал с названием программы и номером слайда. Подробные слайды (6–12 на лекцию, пункты «Тезис — пояснение») пишет отдельный вызов модели; при сбое остаются слайды модуля, а лекция без модели получает шаблонные слайды (цель по РО, понятия, план по минутам, практика, итоги). Если слайдов нет, выводится один слайд «Структура программы» со списком модулей и часами. Требования: SPEC-EXPORT-15, SPEC-CONTENT-16, SPEC-CONTENT-17.

## Тесты: GIFT и Moodle XML

- Обходятся оценочные средства `kit.assessments` с вопросами; для каждого создаётся категория `$course$/<название программы>/<название средства>` (например, «Тест М2» или «Итоговый тест»).
- GIFT: `::<id средства>-<N>:: <вопрос> { =верный ~неверный … }`; служебные символы `~ = # { } : \` экранируются.
- Moodle XML: вопросы `multichoice` с одним верным ответом (`<single>true</single>`), перемешиванием ответов, верный вариант — `fraction="100"`, остальные — `0`; тексты в `CDATA`.

## JSON по схеме 4.8 (`kit_json`)

Корень — объект `program`: id, `org_id`, тип, шаблон, выдаваемый документ, название, объём, аудитория, входной уровень, форма, срок (недели и рабочие дни), календарь, статус, версия, цель, итоговая аттестация, ПС, компетенции (с индикаторами и РО), модули (часы, контроль, эксперт, статус вычитки, темы с часами, весами, пререквизитами и РО), оценочные средства, вопросы, задания, лекции, программы модулей, материалы ИА, источники, разделы, допущения, согласования. Служебные поля состояния (параметры распознавания, расход токенов, прогресс) в выгрузку не входят. Этот же JSON возвращается в поле `kit` ответа автопрогона; эксперту в карточке программы он не отдаётся (`src/app/programs/router.py`).

## Проект приказа (`render_order`)

«ПРИКАЗ № ________________ от «__» ________ 20__ г.», «Об утверждении <шаблон> «<название>»», пункты «Утвердить … объёмом N ак. ч», «Назначить ответственным … ________________», «Контроль … возложить на ________________», подпись руководителя полями и пометка «Проект сформирован автоматически; реквизиты заполняет ответственный сотрудник».

## Пустые поля для людей

| Где | Что остаётся пустым |
|---|---|
| Титул DOCX (`approval`) | номер приказа (после префикса организации), день, месяц, год |
| `authors` | составитель (ФИО, должность), подпись, преподаватели |
| 3.4 Кадровое обеспечение (`conditions_org`) | состав преподавателей (ФИО, должность, модули) |
| Проект приказа | номер, дата, ответственный, контролирующий, подпись руководителя |

Поле — константа `BLANK = '________________'` из `src/app/agent/sections.py`. Правило V-11 считает ошибкой заполненный номер приказа («приказ № 1…»), дату вида «от «12»» и ФИО «Фамилия И. О.» в разделах `approval`, `authors`, `document`; `repair` при такой ошибке пересобирает разделы. Раздел `authors` формируется, но в порядок разделов шаблона (`SECTIONS_DPP`/`SECTIONS_DOOP`) не входит и потому в DOCX не выводится; проверяется только правилом V-11.
