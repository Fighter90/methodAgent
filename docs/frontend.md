# Интерфейс

Интерфейс МетодАгента — одностраничное приложение на React 19, React Router 6 и Vite 6 (TypeScript 5.8, иконки `lucide-react`), исходники в `frontend/src`. Собранный `frontend/dist` раздаёт тот же FastAPI-сервер: `/assets` — статика, все прочие пути, кроме `/api/...`, возвращают `index.html` (`src/app/main.py`). Маршруты и общая оболочка с меню, переключателем ролей и уведомлениями описаны в `App.tsx`, обращения к API — в `api.ts`, страницы — в `pages/`, общие компоненты — в `components/ui.tsx`. Интерфейс скрывает разделы по активной роли, но права всегда проверяет сервер.

## 1. Структура

| Файл | Назначение |
|---|---|
| `main.tsx` | Точка входа: `StrictMode`, `BrowserRouter`, `ToastProvider`, подключение `styles.css` |
| `App.tsx` | Маршруты, оболочка `Shell`, защита маршрутов по ролям |
| `api.ts` | Сессия, запросы к API, ретраи, наблюдение за сервером, вход и смена роли, выгрузка, подписи ролей и статусов |
| `components/ui.tsx` | Тосты, логотип, анимации, спиннер, аватар, тема |
| `pages/*.tsx` | Страницы |
| `styles.css` | Стили (553 строки), светлая и тёмная тема через атрибут `data-theme` |

| Путь | Компонент | Оболочка `Shell` |

| `/login`, `/signin` | перенаправление на `/auth` | — |
| `/register` | перенаправление на `/auth?mode=register` | — |
| `/help` | `Help` | нет |
| `/app` | `Programs` | да |
| `/app/reviews` | `Reviews` | да |
| `/app/kb` | `Kb` | да |
| `/app/admin` | `Admin` | да |

### 2.1. `Shell`

- Без сессии (`getSession()` пуст) — перенаправление на `/auth`.
- **Защита по ролям**: администратор с путей `/app`, `/app/p/...`, `/app/reviews` перенаправляется на `/app/admin`; любой не-администратор с `/app/admin` — на `/app`. Маршрут `/app/kb` отдельно не защищён: пункт меню скрыт от эксперта, а API вернёт ему 403.
- **Меню**: «Программы» — всем, кроме admin; «Вычитка» — expert; «База знаний» — admin, methodist, head; «Администрирование» — admin; «Справка» — всем.
- **Переключатель ролей** — если у пользователя больше одной роли (без `api`); рядом счётчик задач из `GET /me/tasks`. После смены роли эксперт уходит на `/app/reviews` (если не в карточке программы), администратор — на `/app/admin`.
- **Уведомления**: `GET /notifications` и `GET /me/tasks` каждые 15 секунд и при смене страницы; при открытии списка непрочитанные отмечаются `POST /notifications/read {"ids": []}`; показываются 8 последних со ссылкой на программу.
- Переключатель темы, карточка пользователя (ссылка на `/app/me`), кнопка «Выйти» (очищает сессию, переход на `/auth`).
- Событие `ma:offline` показывает тост «Сервер временно недоступен…» (не чаще раза в 20 секунд), `ma:online` — «Связь с сервером восстановлена».

## 3. Клиент API (`api.ts`)

### 3.1. Сессия

Хранится в `localStorage` под ключом `ma.session` как `{token, user}`; ошибки доступа к хранилищу (приватный режим) игнорируются. Событие `ma:user` оповещает компоненты о смене пользователя.

### 3.2. `api(path, opts)`

- URL — `/api/v1${path}`; `opts.json` сериализуется в JSON с `Content-Type: application/json`.
- Токен передаётся в заголовке **`X-MA-Token`**, а не в `Authorization`: прокси хаба перехватывает запросы с `Authorization`.
- **Ретраи**: при сетевой ошибке безопасные запросы (GET, HEAD) повторяются до 3 раз с паузой 1, 2 и 3 секунды. Если не помогло — `probe()`:
  - `probe()` запрашивает `/api/v1/health` с `redirect: 'manual'`: перенаправление, 401, 403 или не-JSON-ответ означают `hub` (истекла сессия хаба), JSON `{"status": "ok"}` — `ok`, иначе `down`;
  - при `hub` страница перезагружается через вход хаба (не чаще раза в минуту, отметка в `sessionStorage`);
  - иначе запускается `watchServer()`: событие `ma:offline` и опрос `probe()` каждые 3 секунды до восстановления (`ma:online`).
- **Ошибки**: из тела берётся `message_ru` (или `detail`) и `details`, бросается `ApiError(status, message, details)`.
- **401 при наличии сессии**: сессия удаляется и, если пользователь не на `/auth`, происходит переход на `/auth?expired=1`.
- Ответ разбирается как JSON, если `content-type` содержит `json`, иначе как текст.

### 3.3. Прочие функции

| Функция | Что делает |
|---|---|
| `login(login, password)` | `POST /auth/login`, сохраняет сессию; учётка с ролью `api` и ролью `methodist` сразу переключается на `methodist` |
| `register(body)` | `POST /auth/register`, сохраняет сессию |
| `switchRole(role)` | `POST /auth/switch-role`, сохраняет новую сессию |
| `waitJob(jobId, onProgress)` | Опрашивает `GET /jobs/{id}` каждые 1,2 секунды до `done` или `failed` |
| `download(programId, fmt)` | Скачивает `GET /programs/{id}/export/{fmt}` с `X-MA-Token`, имя файла из `Content-Disposition` |
| `ROLE_LABEL` | Подписи ролей: методист, эксперт, руководитель, администратор, API |
| `ROLE_CAN` | Для каждой роли — список «может» и строка «не может» (показывается в личном кабинете) |
| `STATUS_LABEL` | Подписи статусов программы (`draft` … `failed`) |
| `NETWORK_MSG` | Текст о недоступности сервера |

## 4. Страницы

### 4.1. `Landing` — `/`

Лендинг: главный экран «Программа обучения…», блоки «Всё, что методист собирает…», «Шесть шагов от запроса…», «Каждый отвечает за своё» (роли), призыв «Соберите первую программу». Использует анимации из `ui.tsx` (`Reveal`, `CountUp`, `useTilt`, `useMouseParallax`, `useScrollY`, `spotlight`).

### 4.2. `Login` — `/auth`

- Загружает `GET /auth/config`: список демо-учёток с паролем (по умолчанию в форме подставлены `madina` / `demo`; если демо-учёток нет — поля пустые), признак регистрации, состояние SSO. При восстановлении связи (`ma:online`) конфигурация перезапрашивается.
- Режим входа: логин или почта и пароль, показ пароля.
- Режим регистрации (`?mode=register`): имя, логин, почта, пароль и подтверждение, согласие на обработку персональных данных; те же проверки, что на сервере (логин по шаблону, пароль от 8 символов с буквой и цифрой).
- После входа: эксперт — `/app/reviews`, администратор — `/app/admin`, остальные — `/app`. После регистрации тост с назначенной ролью.

### 4.3. `Help` — `/help`

Справка пользователя с поиском по разделам: о МетодАгенте, быстрый старт, роли и права, вход и регистрация, шаги 1–6, точечная правка, инструменты методиста, база знаний, администрирование, правила проверки, календарный график, выгрузка, API и автопрогон, модели и стоимость, навыки агента, частые вопросы, глоссарий.

### 4.4. `Programs` — `/app`

- Методисту — форма «Новая программа»: текст запроса, до 5 файлов (перетаскиванием или выбором), режим нормативной базы `gos`/`org`; отправка — `POST /programs/upload`, при наличии `job_id` он сохраняется в `sessionStorage` (`ma.job.<id>`), переход в карточку.
- Список программ (`GET /programs` с фильтрами `status`, `since`, `until`); у руководителя заголовок «Программы организации» и фильтр по умолчанию `on_approval,approved`, у остальных — «Мои программы».
- Методисту — блок «Актуализация старой программы»: загрузка файла в `POST /actualize` и список находок (`FindingsList`).

### 4.5. `Program` — `/app/p/:id`

Загружает `GET /programs/{id}`, продолжает отслеживать задание из `sessionStorage`. В шапке — название, шаблон, объём, версия, статус и затраты на LLM.

Для всех ролей, кроме эксперта, — шаговый мастер:

| Шаг | Компонент | Действия и API |
|---|---|---|
| 1. Запрос | `RequestView`, `Assumptions` | Запрос, параметры и допущения агента |
| 2. Вопросы | `QuestionsView` | Ответы на уточняющие вопросы: `POST .../answers`, затем ожидание задания |
| 3. Каркас | `SkeletonView`, `HoursTable`, `TemplateSwitch`, `EditableText` | Правка часов, названий модулей и тем, цели, компетенций и результатов (`PATCH .../skeleton`), смена шаблона (`POST .../template`), календарный график |
| 4. Проверка | `CheckView`, `RuleList`, `RuleDetails`, `Coverage` | Решения по пунктам «!» (`POST .../skeleton/decisions`), утвердить или вернуть каркас (`POST .../skeleton/approve`) |
| 5. Комплект | `Generation`, `ReportView`, `EditView`, `ExportBlock`, `ToolsPanel` | Прогресс сборки, отчёт автопроверки, покрытие, содержание комплекта, выгрузка, точечная правка (`POST .../edits` с `dry_run` для предпросмотра) |
| 6. Согласование | методист и др.: `TeamView`; руководитель: `ApproveView` | Назначение экспертов (`GET .../experts`, `PUT .../modules/{mid}/expert`), ответы на комментарии (`POST .../comments/answer`), отправка на утверждение (`POST .../submit`), журнал (`GET .../events`); руководитель — утвердить или вернуть (`POST .../approval`), документы и инструменты «текст, версии, актуальность» |

Доступность шагов зависит от статуса: `draft`/`questions` — до шага 2; `skeleton`/`returned` — до 4; `skeleton_approved`/`generating`/`kit_ready` — до 5; остальные — до 6.

Выгрузка (`ExportBlock`): `docx`, `pptx`, `moodle_xml`, `gift`, `json`, `lectures_docx`, `order_draft`.

Эксперт видит `ExpertView`: вычитка назначенного модуля (содержание, отметки элементов), решения `POST .../reviews/decision` (принять элемент или модуль с оценкой, вернуть, задать вопрос), комментарии `POST .../comments` (с запросом правки агенту) и подтверждение предложенных правок через `POST .../comments/answer`, песочница кода своих модулей.

### 4.6. `ProgramTools` (компоненты карточки)

| Компонент | Назначение |
|---|---|
| `EditableText` | Редактируемый текст по месту |
| `TemplateSwitch` | Смена шаблона АЦР (`POST .../template`, затем `GET /programs/{id}`) |
| `ToolsPanel` | Вкладки «Текст программы» (`GET .../sections`), «Версии» (`GET .../versions`, сравнение `.../diff`, откат `.../restore` — только методисту), «Актуализация» (`GET .../actualize`), «Песочница кода» (`GET .../sandbox`), «Адаптация» (`POST .../adapt`, переход в новую программу) |
| `FindingsList` | Список находок актуализации с типами: устаревшая конструкция, снято с поддержки, есть новая версия, недоступно в России, старый источник |

### 4.7. `Reviews` — `/app/reviews`

Для эксперта — `GET /reviews`: карточки назначенных модулей (номер, название, программа, часы, статус вычитки) со ссылкой на программу. Для других ролей запрос не выполняется и показывается подсказка, что раздел доступен эксперту.

### 4.8. `Kb` — `/app/kb`

- «Документы» — `GET /kb/documents`; администратору — загрузка (`POST /kb/documents` с видом документа) и удаление (`DELETE /kb/documents/{id}`).
- Поиск — `POST /kb/search`.
- Только администратору (блок `OrgAdmin`): «Профиль организации» — `GET /org/profile` и сохранение `PUT /org/profile`; «Реестры» — `GET /org/registry?kind=...` и замена раздела `PUT /org/registry`. Методист и руководитель в интерфейсе этих блоков не видят, хотя API разрешает им чтение.
- «Нормативная база агента» — `GET /kb/norms`.

### 4.9. `Admin` — `/app/admin`

Вкладки:

- «Пользователи и роли» — `GET/POST /admin/users`, `PATCH /admin/users/{id}` (роли, данные, пароль, отключение);
- настройки по группам (модель и ключи, лимиты, вход и регистрация, SSO, почта) — `GET/PUT /admin/settings`, состояние шлюза — `GET /llm/status`;
- «Навыки агента» — `GET /admin/skills`, `PUT /admin/skills/{name}` (параметры, инструкция, сброс);
- «Журнал администрирования» — `GET /admin/journal`.

### 4.10. `Me` — `/app/me`

Личный кабинет: логин, текущая и все роли, права роли из `ROLE_CAN`; изменение имени, почты и должности (`PUT /auth/me`), смена пароля (`PUT /auth/me/password`) в блоке «Безопасность»; выход из аккаунта. Данные загружаются из `GET /auth/me`.

## 6. Сборка и стили

| Команда (в `frontend/`) | Действие |
|---|---|
| `npm run dev` | Сервер разработки Vite; прокси `/api`, `/health`, `/docs` на `http://127.0.0.1:8000` |
| `npm run build` | `tsc --noEmit` и `vite build` в `dist/` (`assets/` для статики) |
| `npm run preview` | Просмотр сборки |

Цели сборки: `es2020`, Safari и iOS 14, Firefox 78, Chrome 87, Edge 88 (`vite.config.ts`); `browserslist` в `package.json` дополнительно учитывает долю браузеров в России. PostCSS с `autoprefixer`. Стили — один файл `styles.css` с CSS-переменными (цвета, тени, `--ease`), классами раскладки (`container`, `grid-main`, `row`, `card`, `btn`, `chip`, `tabs`, `stepper`, `table`) и анимациями (`page-enter`, `stagger`, `scaleIn`, `float`); тёмная тема переопределяет переменные по `data-theme="dark"`, а также по системной настройке `prefers-color-scheme: dark`, если тема явно не выбрана светлой.
