# Руководство администратора

Администратор готовит МетодАгент к работе и сопровождает его: заводит пользователей и выдаёт роли, задаёт ключ и модели LLM-шлюза, лимиты и правила входа, настраивает навыки агента, наполняет базу знаний и профиль организации, смотрит журнал. С программами администратор не работает: создаёт их методист, вычитывает эксперт, утверждает руководитель. На такие запросы администратора сервер отвечает 403, а в интерфейсе у него нет разделов «Программы» и «Вычитка» (см. [roles-and-access.md](roles-and-access.md)).

После входа администратор попадает в раздел «Администрирование» (`/app/admin`). В шапке у него три пункта: «База знаний», «Администрирование», «Справка».

## Первый запуск

1. Войдите под `admin` (демо-пароль `demo`) и сразу смените пароль: «Администрирование» → «Пользователи» → «Новый пароль» у строки `admin`, или в личном кабинете.
2. Проверьте, что задан `SECRET_KEY` в окружении сервера. Если его нет, сервер создаёт случайный ключ в `data/runtime/.secret_key`: им подписываются токены входа и шифруются секреты, поэтому файл нужно сохранять при резервном копировании.
3. «Настройки агента» → «Модель и ключи»: адрес шлюза, ключ API, модели. Кнопка проверки показывает состояние шлюза (`GET /api/v1/llm/status`): доступность, израсходованный дневной бюджет, достигнут ли суточный лимит.
4. Заведите реальных пользователей и выключите демо-учётки (`demo_accounts_enabled`), когда начнётся работа с реальными данными.
5. На странице «База знаний» заполните профиль организации и загрузите шаблоны и положения организации.

## Пользователи и роли

Вкладка «Пользователи» (`GET/POST/PATCH /api/v1/admin/users`):

| Действие | Как |
|---|---|
| Создать пользователя | Кнопка «Добавить»: логин, имя, почта, пароль, роли |
| Выдать или снять роль | Щелчок по чипу роли в строке пользователя; ролей может быть несколько |
| Отключить доступ | «Отключить»: пользователь не сможет войти, данные сохраняются |
| Сбросить пароль | «Новый пароль» |

Роли: методист, эксперт, руководитель, администратор. Служебная учётка `api` (роль API и методист) нужна для интеграций и не редактируется. Последнего активного администратора отключить или лишить роли нельзя (ошибка `LAST_ADMIN`). У пользователя с несколькими ролями в шапке появляются кнопки этих ролей; чужую роль так получить нельзя.

## Настройки агента

Вкладка «Настройки агента» (`GET/PUT /api/v1/admin/settings`). Значение из интерфейса перекрывает переменную окружения и действует сразу, без перезапуска. Кнопка «Вернуть значение окружения» отменяет правку. Секреты (ключ API, client secret SSO, пароль почты) хранятся в базе зашифрованными. В интерфейс и API они возвращаются только маской `••••abcd`, в журнал значения не пишутся. Если отправить маску обратно, ключ не перезапишется.

| Группа | Настройка | Ключ | Пояснение |
|---|---|---|---|
| Модель и ключи | Режим генерации | `llm_providers` | `cloudru` — модель шлюза; `fixtures` — без сети, детерминированные ответы навыков |
| | Адрес шлюза | `llm_base_url` | шлюз Cloud.ru Foundation Models |
| | Ключ API | `llm_api_key` | секрет |
| | Модели генерации, судьи, резерва, эмбеддингов | `llm_model_generate`, `llm_model_judge`, `llm_model_reserve`, `llm_model_embed` | |
| | Включить судью | `llm_judge_enabled` | судья тратит токены рассуждающей модели |
| Лимиты | Одновременных запросов к шлюзу | `llm_concurrency` | 1–16, шлюз хакатона допускает 2 |
| | Потоков сборки модулей | `gen_workers` | 1–32 |
| | Таймаут запроса, с | `llm_timeout_s` | 5–900 |
| | Дневной бюджет, ₽ | `llm_daily_budget_rub` | после порога навыки переходят на резервную генерацию |
| | Одновременных заданий | `max_parallel_jobs` | 1–64 |
| | Автопрогонов без токена в час с адреса | `anon_runs_per_hour` | 0 выключает автопрогон без токена |
| | Новых программ в час на пользователя | `programs_per_hour` | по ТЗ 30; сверх — 429 |
| | Новых программ в час для токена api | `api_programs_per_hour` | служебная учётка `api` и токены API с этой ролью |
| Вход и регистрация | Открыта регистрация | `registration_enabled` | |
| | Роль нового пользователя | `registration_default_role` | по умолчанию эксперт: минимальные права |
| | Демо-учётки на форме входа | `demo_accounts_enabled` | учётка admin остаётся всегда |
| | Срок токена доступа, мин | `access_token_expire_minutes` | по ТЗ 30 минут (15 минут – 30 дней); интерфейс продлевает вход токеном обновления на 30 дней |
| SSO | Показывать вход через SSO, протокол, название кнопки, issuer, client ID, client secret | `sso_*` | заготовка: параметры хранятся, подключение протокола в следующей версии |
| Почта | Пароль почты для уведомлений | `smtp_password` | сервер, порт, логин и отправитель задаются в профиле организации |

Полный список переменных окружения: [configuration.md](configuration.md).

## Токены API

Вкладка «Токены API» (`/api/v1/admin/api-tokens`): выдача токена интеграции (владелец — по умолчанию служебная учётка API-клиента, назначение, срок 1–365 дней), список выданных токенов без секретов и отзыв. Значение токена `ma_…` показывается один раз — скопируйте его кнопкой «Копировать»; в базе хранится только хеш. Отозванный или истёкший токен получает 401. Подробности: [roles-and-access.md](roles-and-access.md#61-токены-api-р-04-us-22).

## Навыки агента

Вкладка «Навыки агента» (`GET /api/v1/admin/skills`, `PUT /api/v1/admin/skills/{name}`). Для каждого навыка можно поменять температуру (0–1), лимит токенов (100–32 000), таймаут (5–900 с) и число повторов (0–5). Можно также дописать инструкцию модели. Исходный `SKILL.md` не меняется: переопределения хранятся в `data/skills_overrides.json`. Кнопка «Сбросить к SKILL.md» возвращает исходные параметры. Как устроены навыки: [skills.md](skills.md).

## База знаний и профиль организации

Страница «База знаний» (`/app/kb`):

- **Нормативная база агента.** Встроенные реестры НПА, профстандартов, ФГОС и выжимки актов. Их видят все роли, кроме эксперта. Подробно: [knowledge-base.md](knowledge-base.md).
- **Документы организации.** Загружать и удалять может только администратор (`POST/DELETE /api/v1/kb/documents`). Поддерживаются `.docx`, `.pdf`, `.txt` (формат определяется по содержимому). Текст режется на фрагменты и индексируется эмбеддингами; без модели работает поиск по словам. Загруженные тексты хранятся в `data/runtime/kb` и при выкладке новой версии не затираются.
- **Профиль организации** (`GET/PUT /api/v1/org/profile`). Значения по умолчанию для ответа «На ваше усмотрение» и режима auto, эксперты и их навыки (по ним агент подсказывает экспертов на модули), дублирование уведомлений на почту.
- **Реестры** (`GET/PUT /api/v1/org/registry`). Профстандарты, НПА, литература, версии инструментов с датой проверки.

## Журнал

Вкладка «Журнал» (`GET /api/v1/admin/journal`): регистрации, изменения пользователей, настроек, навыков, профиля и реестров, кто и когда. События по программам (создание, правки, решения людей) видят методист и руководитель в карточке программы.

## Безопасность перед работой с реальными данными

- Смените пароль `admin` и выключите демо-учётки.
- Задайте постоянный `SECRET_KEY` в окружении (не в git).
- Ограничьте `anon_runs_per_hour` или выставьте 0, если автопрогон без токена не нужен.
- Регистрацию оставьте выключенной или с ролью эксперта: новый пользователь не видит чужих программ, пока ему не назначат модуль.
- Делайте резервную копию каталога `data/` (база, загруженные документы, `.secret_key`, переопределения навыков), см. [deployment.md](deployment.md).
