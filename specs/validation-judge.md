# Судья смысловых правил

Префикс требований: `SPEC-JUDGE`. Код: `src/app/validation/judge.py`. Подробности — [docs/validation.md](../docs/validation.md#судья-judgepy). Тесты: `tests/test_spec_judge.py`.

## Назначение

Модель рассуждений уточняет смысловые правила (V-19, V-21, V-22, V-26, V-27), которые код оценивает эвристиками (FR-33). Судья может перевести правило в «предупреждение» с замечаниями, но не снимает замечаний кода; правила не блокирующие. Судья получает сжатое представление программы и сами материалы комплекта — формулировки вопросов с вариантами и ключом, задания с критериями, слайды и планы лекций (MET-33, находка аудита F11: подмена вопроса или ключа и английский текст материалов не меняли вход судьи и оставались незамеченными). Аудит 22.10 (R08, MET-52) добавил во вход судьи блок «итоговая аттестация» (задание `final-task` без `module_id` и вопросы итогового теста `test-final`, которые фильтр по `module_id` раньше отсекал), тела рабочих программ модулей (аннотация и содержание) и строку покрытия, честно показывающую, сколько материалов вошло и что усечено.

## Требования

| ID | Требование | Источник | Тест |
|---|---|---|---|
| SPEC-JUDGE-01 | IF модель не настроена или судья отключён настройкой `llm_judge_enabled`, THEN THE SYSTEM SHALL не вызывать судью и вернуть пустой журнал. | FR-33 | `test_spec_judge.py::test_judge_skipped_when_disabled` |
| SPEC-JUDGE-02 | WHEN судья включён, THE SYSTEM SHALL вызвать модель с навыком и ролью `judge`, температурой 0, лимитом 4096 токенов, схемой `JudgeOut` и текстами правил (V-19, V-21, V-22, V-26, V-27). | FR-33, NFR-09 | `test_spec_judge.py::test_judge_call_parameters` |
| SPEC-JUDGE-03 | THE SYSTEM SHALL передавать судье сжатое представление программы: название, тип, объём, аудиторию, цель, РО, модули с темами, аннотации до 200 символов и последние 3 заметки агента до 160 символов; материалы комплекта передаются по SPEC-JUDGE-07 с усечением. | код | `test_spec_judge.py::test_view_is_compact` |
| SPEC-JUDGE-04 | WHEN судья ответил, THE SYSTEM SHALL заменить `kit.judge` вердиктами `warn` известных правил с непустыми замечаниями (не больше 3, без пробелов по краям, с пометкой `[узел]`, если вердикт указал узел) и вернуть журнал «<правило>: <первое замечание>». | FR-33 | `test_spec_judge.py::test_only_warn_with_messages_kept` |
| SPEC-JUDGE-05 | IF вызов судьи завершился ошибкой, THEN THE SYSTEM SHALL вернуть пустой журнал без исключения, сохранив оценки кода. | FR-33, NFR-08 | `test_spec_judge.py::test_judge_failure_keeps_code_results` |
| SPEC-JUDGE-06 | WHEN замечания судьи сводятся в строки правил (merge — вариант свёртки для прямых вызовов), THE SYSTEM SHALL перевести `pass` в `warn`, не менять `fail`, добавить замечания с префиксом «Судья:», перенести узлы из пометок `[узел]` в `nodes` и не трогать правила без замечаний судьи. | FR-33 | `test_spec_judge.py::test_merge_adds_judge_messages` |
| SPEC-JUDGE-07 | WHEN формируется вход судьи, THE SYSTEM SHALL передавать ему по каждому модулю реальные материалы: формулировки вопросов с вариантами и отмеченным ключом (до 12 на модуль, формулировка до 200 символов, вариант до 60), задания с критериями и баллами (до 6), заголовки и пункты слайдов (до 10) и строки планов лекций (до 12); IF материалов больше лимитов или превышен бюджет около 9000 символов на модуль, THEN THE SYSTEM SHALL усечь их с пометкой «усечено». | MET-33, F11 | `test_spec_judge.py::test_view_contains_real_materials`, `test_spec_judge.py::test_view_truncates_materials` |
| SPEC-JUDGE-08 | WHEN формируется отчёт этапа `kit` при непустых замечаниях судьи, THE SYSTEM SHALL добавить их отдельными строками (`kind=llm`, `check=None`, `status=warn`, id «<правило>-judge») с узлами из пометок `[узел]`, не добавляя эти замечания к сообщениям кода; в списке действий они выводятся строками «Судья (…): …». | MET-33, F11 | `test_spec_judge.py::test_judge_rows_separate_from_code`, `test_spec_judge.py::test_audit_counterexample_is_caught` |
| SPEC-JUDGE-09 | WHEN формируется вход судьи, THE SYSTEM SHALL передавать ему блок «итоговая аттестация»: форма и часы, задание `final-task` (формулировка, ожидаемый результат, критерии с баллами, РО) и вопросы итогового теста (`assessment_id='test-final'`) с лимитами усечения, как у материалов модулей; IF задание или вопрос итогового теста заменены, THEN THE SYSTEM SHALL включить новый текст во вход судьи, чтобы замена стала видна модели; вопросы итогового теста в материалах модулей не дублируются. | аудит 22.10 (R08) | `test_spec_judge.py::test_view_contains_final_assessment`, `test_spec_judge.py::test_final_swap_is_visible_to_judge` |
| SPEC-JUDGE-10 | WHEN формируется вход судьи, THE SYSTEM SHALL передавать ему тело рабочей программы каждого модуля (аннотация и содержание `ModuleProgram.content` порциями); IF текст длиннее порции, THEN THE SYSTEM SHALL усечь его с «…» и указанием исходной длины, чтобы вставка любого текста в рабочую программу меняла вход судьи. | аудит 22.10 (R08) | `test_spec_judge.py::test_view_contains_module_program_bodies` |
| SPEC-JUDGE-11 | THE SYSTEM SHALL завершать вход судьи строкой покрытия «Показано N% материалов», вычисленной по символам (показано/полно), со списком усечённого («усечено: …») и непоместившихся обязательных материалов («не показано: …» с числом скрытых символов); IF материалы помещаются целиком, THEN THE SYSTEM SHALL показать 100% без списка. | аудит 22.10 (R08) | `test_spec_judge.py::test_view_reports_materials_coverage` |
| SPEC-JUDGE-12 | WHEN замечания судьи относятся к итоговой аттестации (узел `final-task` или вопрос `qf.*`), THE SYSTEM SHALL привязать строку отчёта к узлу итогового задания `final-task` в дополнение к узлу вопроса. | аудит 22.10 (R08) | `test_spec_judge.py::test_final_judge_rows_anchor_to_final_task` |

## Вне области

Качество суждений модели, промпт судьи, условие запуска при исчерпанном суточном лимите (проверяется в `generate_kit`), эвристики правил кодом ([validation-rules.md](validation-rules.md)). При ошибке судьи прежнее содержимое `kit.judge` не очищается — поведение не специфицировано. Судья не влияет на блокирующие проверки: его замечания всегда `warn`.
