# Администратору

Администратор готовит МетодАгент к работе и сопровождает его: заводит пользователей и выдаёт роли, задаёт ключ и модели LLM-шлюза, лимиты и правила входа, настраивает навыки агента, наполняет базу знаний и профиль организации, смотрит журнал.

С программами администратор не работает: их создаёт методист, вычитывает эксперт, утверждает руководитель. Это разделение соответствует таблице 19 ТЗ. На запросы администратора к программам сервер отвечает `403`, а в интерфейсе у него нет разделов «Программы» и «Вычитка».

Демо-учётка: `admin`, пароль `demo`. После входа вы попадаете в «Администрирование» (`/app/admin`). В шапке три пункта: «База знаний», «Администрирование», «Справка».

## Чек-лист первого запуска

1. **Смените пароль `admin`.** «Администрирование» → «Пользователи» → «Новый пароль» в строке `admin`, или в личном кабинете.
2. **Проверьте `SECRET_KEY`.** Если его нет в окружении сервера, сервер создаёт случайный ключ в `data/runtime/.secret_key`. Им подписываются токены и шифруются секреты, поэтому файл нужно сохранять в резервных копиях.
3. **Подключите модель.** «Настройки агента» → «Модель и ключи»: адрес шлюза, ключ API, модели. Кнопка проверки вызывает `GET /api/v1/llm/status` и показывает доступность шлюза, израсходованный дневной бюджет и признак суточного лимита.
4. **Заведите пользователей** и выдайте роли.
5. **Заполните профиль организации** и загрузите шаблоны и положения на странице «База знаний».
6. **Выключите демо-учётки** (`demo_accounts_enabled`), когда начнётся работа с реальными данными.

## Пользователи и роли

Вкладка «Пользователи».

| Действие | Как |
|---|---|
| Создать пользователя | «Добавить»: логин, имя, почта, пароль, роли |
| Выдать или снять роль | Щелчок по чипу роли в строке пользователя. Ролей может быть несколько |
| Отключить доступ | «Отключить»: пользователь не сможет войти, данные сохраняются |
| Сбросить пароль | «Новый пароль» |

Роли: методист, эксперт, руководитель, администратор. Служебная учётка `api` (роли API и методист) нужна для интеграций и не редактируется.

Требования к данным:

| Поле | Правило |
|---|---|
| Логин | строчная латиница, цифры, `.`, `_`, `-`; 3–32 символа, начинается с буквы или цифры (шаблон `^[a-z0-9][a-z0-9._-]{2,31}$`); уникальный |
| Почта | формат `x@y.z`, уникальная |
| Пароль | не меньше 8 символов, хотя бы одна буква и одна цифра |
| Роли | хотя бы одна |

Последнего активного администратора отключить или лишить роли нельзя: сервер ответит `409 LAST_ADMIN`.

У пользователя с несколькими ролями в шапке появляются кнопки этих ролей. Каждая кнопка выдаёт новый токен с выбранной ролью; роль, которой у пользователя нет, так получить нельзя.

### Пример: новый методист

1. «Добавить» → логин `ivanova`, имя «Иванова Е.», пароль `Metod2026`, роль «методист».
2. Сообщите сотруднику логин и временный пароль.
3. Сотрудник входит и меняет пароль в личном кабинете («Безопасность»).

## Настройки агента

Вкладка «Настройки агента». Значение из интерфейса перекрывает переменную окружения и действует сразу, без перезапуска. Кнопка «Вернуть значение окружения» отменяет правку.

| Группа | Настройка | Ключ | Пояснение |
|---|---|---|---|
| Модель и ключи | Режим генерации | `llm_providers` | `cloudru` — модель шлюза; `fixtures` — без сети, детерминированные ответы навыков |
| | Адрес шлюза | `llm_base_url` | шлюз Cloud.ru Foundation Models |
| | Ключ API | `llm_api_key` | секрет |
| | Модели генерации, судьи, резерва, эмбеддингов | `llm_model_generate`, `llm_model_judge`, `llm_model_reserve`, `llm_model_embed` | |
| | Включить судью | `llm_judge_enabled` | судья тратит токены рассуждающей модели |
| Лимиты | Одновременных запросов к шлюзу | `llm_concurrency` | 1–16; шлюз хакатона допускает 2 |
| | Потоков сборки модулей | `gen_workers` | 1–32 |
| | Таймаут запроса, с | `llm_timeout_s` | 5–900 |
| | Дневной бюджет, ₽ | `llm_daily_budget_rub` | после порога навыки переходят на резервную генерацию |
| | Одновременных заданий | `max_parallel_jobs` | 1–64 |
| | Автопрогонов без токена в час с адреса | `anon_runs_per_hour` | 0 выключает автопрогон без токена |
| Вход и регистрация | Открыта регистрация | `registration_enabled` | |
| | Роль нового пользователя | `registration_default_role` | по умолчанию эксперт; допускаются эксперт, методист, руководитель |
| | Демо-учётки на форме входа | `demo_accounts_enabled` | учётки `admin` и `api` работают всегда |
| | Срок токена доступа, мин | `access_token_expire_minutes` | 15 минут – 30 дней (по умолчанию 30 минут; вход продлевается токеном обновления на 30 дней) |
| SSO | Кнопка SSO, протокол, название, issuer, client ID, client secret | `sso_*` | заготовка: параметры хранятся, протокол подключается в следующей версии |
| Почта | Пароль почты | `smtp_password` | сервер, порт, логин и отправитель задаются в профиле организации |

### Секреты

Ключ API, client secret SSO и пароль почты хранятся в базе зашифрованными ключом, производным от `SECRET_KEY`. В интерфейс и API они возвращаются только маской `••••abcd` (последние четыре символа), в журнал значения не пишутся. Если отправить маску обратно, секрет не перезапишется.

Если `SECRET_KEY` сменился, старые секреты не расшифруются: сервер напишет предупреждение в журнал приложения и возьмёт значение из окружения. Введите секрет заново.

Полный список переменных окружения — на странице [Настройки](Настройки).

## Навыки агента

Вкладка «Навыки агента». Для каждого навыка можно поменять:

| Параметр | Диапазон |
|---|---|
| Температура | 0–1 |
| Лимит токенов | 100–32 000 |
| Таймаут, с | 5–900 |
| Число повторов | 0–5 |
| Инструкция модели | текст не короче 20 символов |

Исходный `SKILL.md` не меняется: переопределения хранятся в `data/runtime/skills_overrides.json`. Кнопка «Сбросить к SKILL.md» возвращает исходные параметры.

> Бюджет времени навыка равен `таймаут × (повторы + 1)`. Если модель не уложилась, навык уходит в резервную генерацию. Увеличивая таймаут `content`, помните, что сборка комплекта станет дольше.

Модель вызывают только навыки `intake`, `skeleton`, `content` и `review_assist`. Остальные навыки реализованы кодом, и их параметры модели не влияют на результат. Подробно — [Как работает агент](Как-работает-агент).

## База знаний и профиль организации

Страница «База знаний» (`/app/kb`).

**Нормативная база агента.** Встроенные реестры НПА, профстандартов и ФГОС и 52 выжимки актов. Их видят все роли, кроме эксперта.

**Документы организации.** Загружать и удалять может только администратор. Поддерживаются `.docx`, `.pdf`, `.txt` (до 20 МБ); формат определяется по содержимому. Виды документов: шаблон программы, положение, иной документ. Текст режется на фрагменты и индексируется эмбеддингами; если модель недоступна, работает поиск по словам. Загруженные тексты хранятся в `data/runtime/kb` и при выкладке новой версии не затираются.

**Профиль организации.** Название, шапка, реквизиты, адрес, город, префикс номера приказа, значения по умолчанию для ответа «На ваше усмотрение» и режима auto, эксперты и их навыки (по ним агент подсказывает экспертов на модули), дублирование уведомлений на почту и настройки SMTP. Пароль SMTP в профиль положить нельзя: он задаётся настройкой `smtp_password` или переменной `SMTP_PASSWORD`.

**Реестры.** Профстандарты, НПА, литература и версии инструментов с датой проверки. Раздел заменяется целиком. Подробности и ограничения — [Нормативная база](Нормативная-база).

### Пример: шаблон организации в генерации

1. «База знаний» → «Документы» → загрузите `.docx` шаблона программы с видом «Шаблон программы».
2. Методист при создании программы выбирает нормативную основу «Документы организации».
3. При сборке каркаса агент найдёт до 4 подходящих фрагментов, добавит документ в нормативную базу программы и, если у референсов нет своей структуры, возьмёт структуру разделов из первого загруженного шаблона.

## Журнал

Вкладка «Журнал»: регистрации, смены паролей, создание и изменение пользователей, изменения настроек (только названия полей, без значений), навыков, профиля и реестров. Видно, кто и когда.

События по программам (создание, правки, решения людей) администратор не видит: их смотрят методист и руководитель в карточке программы.

## Безопасность перед работой с реальными данными

- Смените пароль `admin` и выключите демо-учётки.
- Задайте постоянный `SECRET_KEY` в окружении (не в git).
- Ограничьте `anon_runs_per_hour` или выставьте 0, если автопрогон без токена не нужен.
- Регистрацию оставьте выключенной или с ролью эксперта: новый пользователь не видит чужих программ, пока ему не назначат модуль.
- Делайте резервную копию каталога `data/runtime/`: база, загруженные документы, `.secret_key`, переопределения навыков. См. [Развёртывание](Развёртывание).

## Подсказки

- **Пользователь зарегистрировался, но ничего не видит.** Так и задумано: он эксперт без модулей. Выдайте нужную роль на вкладке «Пользователи».
- **Новый ключ API не работает.** Нажмите проверку шлюза: поле `error` покажет тип ошибки. Изменения настроек применяются со следующего запроса к модели.
- **Агент собирает всё «по шаблону».** Проверьте `/api/v1/llm/status`: возможно, исчерпан дневной бюджет (`spent_today_rub` ≥ `daily_budget_rub`) или суточный лимит шлюза (`daily_limit_reached`). Лимит сбрасывается в 00:00 МСК.
- **Хочу добавить акт в нормативную базу.** Через `PUT /api/v1/org/registry` или правкой файлов реестра с перезапуском. Пошагово — [Нормативная база](Нормативная-база).
