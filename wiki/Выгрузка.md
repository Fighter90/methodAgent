# Выгрузка

Готовый комплект выгружается в семь форматов. Выгрузку выполняет код (`src/app/export/service.py`, навык `export`) без участия модели, поэтому одинаковая программа всегда даёт одинаковые файлы.

Реквизиты приказа, ФИО преподавателей и подписи остаются пустыми полями `________________`: их заполняет человек. Правило V-11 проверяет, что агент их не заполнил.

## Форматы

| `fmt` | Файл | Что внутри | Для кого |
|---|---|---|---|
| `docx` | `<имя>.docx` | Программа по шаблону АЦР с титульным листом, таблицами и приложениями | Методист, руководитель, учебный отдел |
| `lectures_docx` | `<имя>_lectures.docx` | Лекции: длительность, план по минутам, примеры кода, тезисы слайдов | Преподаватели |
| `order_draft` | `<имя>_order_draft.docx` | Проект приказа об утверждении программы | Делопроизводство |
| `pptx` | `<имя>.pptx` | Слайды лекций | Преподаватели |
| `gift` | `<имя>.gift.txt` | Тесты в формате GIFT | Администратор LMS |
| `moodle_xml` | `<имя>_moodle.xml` | Тесты в Moodle XML | Администратор LMS |
| `json` | `<имя>.json` | Весь комплект по схеме подраздела 4.8 ТЗ | Интеграции |

Имя файла — название программы, где всё, кроме букв, цифр и дефиса, заменено на `_` (до 60 символов). PDF в коде не реализован.

## Как скачать

**В интерфейсе.** Карточка программы → блок «Документы» → кнопка нужного формата.

**Через API:**

```bash
curl -s -OJ https://<хост>/api/v1/programs/<program_id>/export/docx \
  -H "Authorization: Bearer $TOKEN"
```

Выгрузка доступна методисту, руководителю и API-клиенту (только для своих программ). Эксперту и администратору выгрузка запрещена. Ответ автопрогона содержит ссылки на все форматы в поле `files`.

## DOCX по шаблону АЦР

Шрифт Times New Roman 12 pt, заголовки первого уровня — зелёным акцентом. Порядок и заголовки разделов — по шаблону ДПП ПК или ДООП.

**Титульный лист:** шапка организации, реквизиты и адрес из профиля организации, блок «УТВЕРЖДЕНО Приказом № ____-<префикс> от «___» __________ 20__ г.», вид программы, название, город и год.

Вид программы на титуле:

| Тип | Строка на титуле |
|---|---|
| ДПП ПК | ДОПОЛНИТЕЛЬНАЯ ПРОФЕССИОНАЛЬНАЯ ПРОГРАММА ПОВЫШЕНИЯ КВАЛИФИКАЦИИ |
| Стажировка | … В ФОРМЕ СТАЖИРОВКИ |
| ДООП | ДОПОЛНИТЕЛЬНАЯ ОБЩЕОБРАЗОВАТЕЛЬНАЯ ОБЩЕРАЗВИВАЮЩАЯ ПРОГРАММА |

**Специальные разделы:**

| Раздел | Содержимое |
|---|---|
| Результаты (ДПП) | Таблица «Виды деятельности / Профессиональные компетенции / Практический опыт / Умения / Знания» |
| Учебный план | ДПП: №, раздел, всего, ЛК, ПР, ЛБ, СРС, форма аттестации, строки «Итоговая аттестация» и «Итого (час.)». ДООП: общая трудоёмкость, аудиторные, теория, практика, самостоятельная работа, форма контроля |
| УТП | ДПП: учебный план с темами. ДООП: таблица «Тема / Виды учебных занятий / Содержание / Часы» |
| Календарный график (2.3) | Таблица по неделям: учебные дни, всего, ЛК, ПР, ЛБ, СРС, ИА, содержание |
| Рабочая программа (ДПП) | Разделы с аннотацией, темы с содержанием и часами по видам, текущий контроль, ИА, итого |
| Оценивание (ДООП) | Таблица этапов контроля «Этап / Артефакт / Кто и как оценивает» |
| Приложение 1 | Для стажировки — примерные вопросы собеседования; затем тесты с вариантами «а)…е)» и ключом, задания с ожидаемым результатом и критериями |
| Приложение 2 (только ДПП) | Методические указания к ИА, требования к работе, критерии с баллами, порог «зачтено» — 70 % максимального балла, процедура (выступление 5–7 минут и ответы на вопросы 5–7 минут) |

Перед каждым приложением — разрыв страницы. В шаблоне ДООП одно приложение.

## PPTX

Формат 16:9. Титульный слайд — название программы, шаблон и объём. Далее по слайду на каждый слайд лекций: заголовок, тезисы (22 pt), заметки докладчика, зелёная полоса сверху. Если слайдов нет, выводится один слайд «Структура программы» со списком модулей и часами.

## Тесты: GIFT и Moodle XML

Для каждого оценочного средства с вопросами создаётся категория `$course$/<название программы>/<название средства>`, например «Тест М2» или «Итоговый тест».

Пример GIFT:

```
$CATEGORY: $course$/Анализ данных на Python/Тест М2

::test-m2-1:: Какой метод pandas группирует строки по значению столбца? { =groupby ~merge ~pivot ~concat }
```

Идентификатор вопроса — `<id средства>-<N>`: `test-m2` для теста модуля 2, `test-final` для итогового теста. Служебные символы `~ = # { } : \` экранируются.

Moodle XML: вопросы `multichoice` с одним верным ответом, перемешиванием ответов, верный вариант — `fraction="100"`, остальные — `0`; тексты в `CDATA`.

**Как импортировать в Moodle:** «Банк вопросов» → «Импорт» → формат «Moodle XML» (или «GIFT») → загрузите файл. Категории создадутся автоматически.

## JSON по схеме 4.8

Корень — объект `program`:

```json
{
  "program": {
    "id": "prg-…", "org_id": "acr", "type": "dpp_pk", "template": "…", "issued_document": "…",
    "title": "…", "volume_h": 72, "audience": "…", "entry_level": "…", "form": "…",
    "duration": {"weeks": 4, "work_days": 20},
    "calendar": {"…": "…"},
    "status": "kit_ready", "version": 5, "goal": "…",
    "final_assessment": {"form": "…", "hours": 4, "description": "…"},
    "profstandard": {"code": "…", "title": "…", "order": "…", "confirmed": true, "tf": []},
    "competencies": [], "modules": [],
    "assessments": [], "questions": [], "tasks": [], "lectures": [], "module_programs": [],
    "final_assessment_materials": {},
    "sources": [], "sections": {}, "assumptions": [], "approvals": []
  }
}
```

Служебные поля состояния (распознанные параметры, уточняющие вопросы, референсы, отчёт, решения, комментарии, расход токенов, прогресс, заметки агента) в выгрузку не входят. `sources` объединяет нормативную базу и литературу; неподтверждённые источники имеют `confirmed: false`. Тот же JSON возвращается в поле `kit` ответа автопрогона. Подробнее о полях — [Модель данных](Модель-данных).

## Проект приказа

«ПРИКАЗ № ________________ от «__» ________ 20__ г.», «Об утверждении <шаблон> «<название>»», пункты «Утвердить … объёмом N ак. ч», «Назначить ответственным … ________________», «Контроль … возложить на ________________», подпись руководителя полями и пометка «Проект сформирован автоматически; реквизиты заполняет ответственный сотрудник».

## Пустые поля для людей

| Где | Что остаётся пустым |
|---|---|
| Титул DOCX | номер приказа (после префикса организации), день, месяц, год |
| Авторы | составитель (ФИО, должность), подпись, преподаватели |
| 3.4 Кадровое обеспечение | состав преподавателей (ФИО, должность, модули) |
| Проект приказа | номер, дата, ответственный, контролирующий, подпись руководителя |

Раздел авторов формируется и проверяется правилом V-11, но в порядок разделов шаблона не входит и в DOCX не выводится.

## Частые вопросы

- **Где PDF?** PDF не реализован. Откройте DOCX в текстовом редакторе и сохраните как PDF.
- **Почему эксперт не может скачать файлы?** По правам эксперт видит только свои модули, а выгрузка содержит всю программу.
- **Можно ли выгрузить до утверждения?** Да. Выгрузка доступна, как только есть данные; утверждение руководителем не требуется.
