# Быстрый старт

На этой странице три пути: попробовать демо за пять минут, запустить МетодАгент у себя без Docker и запустить его в Docker.

## 1. Демо за пять минут

### Вход

1. Откройте https://methodagent.ru. Адрес переадресует на стенд в хабе хакатона.
2. Войдите в хаб: у него свой вход, отдельный от приложения.
3. На странице входа приложения (`/auth`) нажмите плитку демо-пользователя или введите логин и пароль вручную.

| Логин | Пароль | Роль | Куда попадёте после входа |
|---|---|---|---|
| `madina` | `demo` | методист | «Программы» |
| `timur` | `demo` | эксперт | «Вычитка» |
| `olga` | `demo` | эксперт | «Вычитка» |
| `ahmed` | `demo` | руководитель | «Программы» (фильтр «На утверждении» и «Утверждена») |
| `admin` | `demo` | администратор | «Администрирование» |
| `api` | `demo` | служебный API-клиент | в интерфейсе работает как методист |

Демо-учётки можно выключить в настройках администратора. Тогда их плиток на форме нет, а вход под ними отклоняется (кроме `admin` и `api`).

### Первая программа шаг за шагом

Ниже сценарий для методиста `madina`.

**Шаг 1. Запрос.** «Программы» → «Новая программа». Вставьте, например:

> Нужна программа повышения квалификации на 72 часа «Анализ данных на Python» для сотрудников банков, формат очно-заочный, срок 4 недели, итоговая аттестация — защита проекта.

По желанию приложите референс (`.docx`, `.pdf`, `.txt`, до 5 файлов, каждый до 20 МБ) и выберите нормативную основу: «Госстандарты» (по умолчанию) или «Документы организации». Из референса агент берёт только структуру разделов, а таблицы часов в нём проверяет на сходимость.

**Шаг 2. Вопросы.** Если в запросе не хватает обязательных сведений (тип программы, объём, аудитория и её уровень, форма обучения, форма итоговой аттестации), агент задаст до пяти вопросов с вариантами ответа. Кнопка «На ваше усмотрение» берёт значение из профиля организации и записывает его в допущения. В примере выше все сведения есть, поэтому вопросов, скорее всего, не будет.

**Шаг 3. Каркас.** Агент покажет цель, компетенции, модули и темы с часами, профстандарт, нормативную базу и календарный график. Часы в жёлтых полях можно менять: итоги и проверки пересчитываются сразу. Названия, формулировки и цель правятся щелчком по тексту.

**Шаг 4. Проверка.** Отчёт показывает правила со статусами ✓, ! и ✕. По каждому пункту «!» агент показывает предложение: нажмите «Принять» или «Оставить как есть». Пока есть ✕ или нерешённые «!», кнопка «Утвердить каркас» недоступна.

**Шаг 5. Комплект.** После утверждения агент соберёт материалы по модулям. На экране видны прогресс по модулям, лента событий, токены, стоимость и прогноз времени. В конце появится отчёт автопроверки, содержание комплекта и кнопки выгрузки.

**Шаг 6. Согласование.** Назначьте экспертов на модули (агент подсказывает подходящих), затем выйдите и войдите как `timur`, примите элементы и модуль. Вернитесь под `madina`, отправьте программу руководителю и утвердите её под `ahmed`.

> Совет. Чтобы быстро пройти все роли в одном браузере, пользуйтесь кнопкой «Выйти» в шапке и плитками демо-пользователей на форме входа.

### Автопрогон без интерфейса

Тот же результат можно получить одним запросом. Без токена такой запрос разрешён, но не больше 12 раз в час с одного адреса:

```bash
curl -X POST 'https://tochka-sborki-2026-team-098.hub.gigaschool.ru/api/v1/programs?mode=auto' \
  -H 'Content-Type: application/json' \
  -d '{"request": "Программа ПК «Анализ данных на Python», 72 часа, 4 недели, итог — защита проекта"}'
```

Учтите, что стенд стоит за входом хаба: из командной строки удобнее работать с локальным запуском. Подробнее — на странице [API](API).

## 2. Локальный запуск без Docker

Понадобятся Python 3.12 и Node.js 22 (так собирается образ; README допускает Node 20+).

```bash
git clone <адрес репозитория> metodagent && cd metodagent
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env                  # при необходимости задайте LLM_API_KEY
cd frontend && npm ci && npm run build && cd ..
PYTHONPATH=src uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте http://localhost:8000. Что произойдёт при первом запуске:

- создастся каталог `data/runtime/` с базой `metodagent.db`;
- если `SECRET_KEY` не задан, сгенерируется случайный ключ в `data/runtime/.secret_key`;
- появятся демо-учётки с паролем `demo`.

**Без ключа модели.** Поставьте в `.env` строку `LLM_PROVIDERS=fixtures`. Тогда сеть не нужна, навыки сразу идут в детерминированную резервную генерацию, а часы, проверки и выгрузка работают как обычно. Это удобно для знакомства и разработки.

**С ключом.** Укажите `LLM_API_KEY` и при необходимости `LLM_BASE_URL` (по умолчанию `https://foundation-models.api.cloud.ru/v1`). Ключ можно задать и позже, в интерфейсе администратора.

**Режим разработки интерфейса.** `cd frontend && npm run dev` запускает Vite с прокси `/api`, `/health`, `/docs` на `127.0.0.1:8000`.

Если интерфейс не собран, на `/` сервер отдаёт JSON с указанием на `/docs`; API работает.

## 3. Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f app
```

Что важно знать:

- `docker-compose.yml` подключает `env_file: /opt/hackathon/ai.env`. Вне ВМ хакатона создайте этот файл (можно пустой) или уберите строку `env_file`.
- Данные лежат в томе `./data:/app/data`, журналы — в `./logs`. Контейнер работает только для чтения, поэтому всё изменяемое пишется в `data/runtime`.
- `SECRET_KEY`, `LLM_PROVIDERS`, `LLM_JUDGE_ENABLED` пробрасываются из окружения оболочки или `.env`.
- На ВМ удобнее скрипт `./scripts/deploy_vm.sh`: он сам допишет `SECRET_KEY`, соберёт образ, настроит автозапуск и проверит `/health`.

Проверка, что сервис жив:

```bash
curl -s http://localhost:8000/health
# {"status": "ok", "version": "0.1.0", "llm": false}
```

`"llm": false` значит, что ключ шлюза не задан или выбран режим `fixtures`. Сервис при этом работает на резервной генерации.
